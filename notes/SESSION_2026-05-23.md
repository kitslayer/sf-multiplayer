## What lives and what got reverted (current behavior)

### ✅ Still active (shipped, not reverted)

- **P0-12** — `MapInfoSync` Vector2 key quantization to 0.01 precision. Harmony prefixes on `AddMapDataObject` + `OnMapDataRecieved` on both server and client sides. Fixes silent GhostPlatform lookup failures from float ULP drift.
- **P0-13** — Full-keyframe snapshot to each new v26 endpoint on first PlayerInput. Late-joining clients now see current at-rest box positions instead of prefab spawns.
- **P0-14** — v26.5 wire-format `MapInfoSyncable` section. Server-authoritative position broadcast for `MoveAlongPathUsingForce` / `PillarHandler` / `GhostPlatform`. Client makes their rigidbodies kinematic on first sight so local AddForce/spring doesn't fight the snapshot.
- **P0-15** — `DestructiblePiece.OnCollisionEnter` guard in `SFClientRecon`. Suppresses destructions when colliding body was snapshot-lerped >0.3u in the last 150ms. Catches the swept-lerp-into-ice teleport case.
- **Phase 6.12.2 v1.0** — Shift-correction reconciliation. The local-player path no longer "snaps to stale server position"; instead applies `drift = server_at_seq_N − predicted_at_seq_N` as a positional offset to the current local position. Velocity preserved. Canonical CSGO/Valorant model. Thresholds: 0.3u ignore, 0.3u+ apply silently, 2.5u+ apply + warn-log.
- **Phase 6.17 v0.2** — Server-side projectile hit registration. Swept sphere-sphere (radius 1.2u) per projectile per tick. On hit, server emits authoritative `PktPlayerTookDamage` on the victim's mEventChannel.
- **Phase 6.17 v0.3** — Particle direction bytes in the damage body (visual hit feedback) + wall occlusion via `Physics.Linecast`. Bullets now stop at walls; player rigs (Controller in root) excluded from wall-hit detection.
- **Phase 6.20** — Chat command suite (`/weapons`, `/kick`, `/anticheat`, `/map`, `/listmaps`, `/tickrate`, plus the existing `/code`, `/ping`, `/players`, `/lobbies`, `/start`, `/restart`, `/next`, `/version`, `/help`).
- **TOCs** at the top of `SFHeadlessHost.cs` and `SFClientRecon.cs` for GitHub navigation.
- **serve-lobbies.py** card-layout HTML view + `/healthz` endpoint.

## Architectural state at end of session

### Authority model (current)

- **Player positions**: hybrid. Client sends `PktPlayerInput` to server (60Hz). Server's auth rig runs Movement.cs from those inputs. v26 snapshot broadcasts authoritative position back. Local client also runs its own Movement.cs for prediction; shift-correction (Phase 6.12.2 v1.0) folds server corrections in.
- **NSO positions (boxes, ice, chains, crates)**: oracle is sole authority. Clients are kinematic (back to stock SF behavior after the revert). NSO.TickSyncPos at 5Hz + v26 snapshot at 30Hz drive client positions.
- **NSO destruction events**: client-initiated only. Player rig (dynamic) collides with NSO (kinematic) → fires `DestructiblePiece.OnCollisionEnter` → `SendDestructMessage` → server → relayed to all via `RelayBodyToAll`. Server-side destructions are filtered out (back to drop-all after P0-11 revert).
- **MapInfoSyncableBase (moving platforms, pillars, ghost platforms)**: oracle authoritative. v26.5 snapshot section carries `[startX, startY, x, y, z]` per object. Client kinematic-flips them on first sight + lerps toward server target.
- **Projectiles**: oracle simulates trajectories. Hit detection via swept sphere check (radius 1.2u) + wall occlusion. Server emits authoritative damage on hit. Client visually renders projectile from snapshot position.
- **Damage events**: client-emitted currently. Server validates magnitude + attacker bounds + range. Server-side hit reg (Phase 6.17 v0.2) emits its OWN damage for shots that hit player rigs.

### Wire protocol versions

- v25 = stock SF (msgTypes 0-38)
- v25 patched DLL adds 56 (LerpPlayer), 57 (ColorChanged) — both relayed blindly
- **v26.5 (current)**: adds 39 (WorldStateSnapshot), 40 (PlayerInput), 41 (ClientFireWeapon). Snapshot body shape includes players + NSOs + projectiles + mapSync sections in that order. Full spec in [`PROTOCOL.md`](PROTOCOL.md).

### Server-side performance state

- Server physics tickrate: 60Hz (`/tickrate` adjustable, env override `SF_ROUND_END_DELAY` doesn't exist for this — only the round-end and next-match delays are env-tunable)
- Snapshot broadcast: 30Hz wall-clock
- Round-end delay: 0.5s after killing-blow (was 2.5s before `f084df6`)
- Next-match delay: 2.0s after MapChange (was 3.0s)
- Both tunable via `SF_ROUND_END_DELAY` / `SF_NEXT_MATCH_DELAY` env vars
