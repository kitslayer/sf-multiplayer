## 0. LIVE INCIDENT found during review (act first)

**The production oracle (MAIN, 69.53.117.43:1337) has been dead-but-looks-alive since 2026-06-10 ~18:25 UTC.**

Evidence chain:

- **New root-cause clues** (not in CRASH_INVESTIGATION.md): (a) strict ~24h-uptime periodicity ⇒ time/counter-triggered, not load-triggered; (b) the faulting address `0x7f800004` = float **+Infinity** bit pattern + 4 — consistent with an accumulating float timer reaching Inf/garbage and being reinterpreted as an object pointer whose refcount is then incremented. Fresh `crash.dmp` + `error.log` land daily in `~/sf-oracle/install/2026-*/`.
- Today's 18:21:46 restart **crashed again at 18:25:18** (same EIP, 3.5 min in), and this time Unity's crash handler **wedged the process instead of exiting**: pid alive 7+ h with CPU frozen at 10m55s, plugin log stopped at heartbeat tick 40, `rx=0.0/s`, healthcheck DOWN even on loopback while the socket stays bound.
- **Every monitoring layer is blind to this state**: systemd sees an active unit (no exit ⇒ `Restart=on-failure` never fires); `serve-lobbies.py` `/healthz` hardcodes static `MAIN` as `alive:true` (see finding R-7); sf-monitor sees a live pid.

Immediate: `sudo systemctl restart sf-oracle`.

Durable fixes (ordered):
1. `RuntimeMaxSec=82800` (23 h) in `sf-oracle.service` — converts the daily uncontrolled crash into a controlled nightly restart inside the crash-free window.
2. Real liveness: a systemd timer running `healthcheck.py --host 127.0.0.1 --port 1337` that restarts the unit after N consecutive failures (catches both the wedge and any future deaf state). `WatchdogSec` can't see a wedged Wine child; an external probe can.
3. Make `/healthz` actually probe static lobbies instead of hardcoding `alive:true` (R-7).
4. Update `notes/CRASH_INVESTIGATION.md` with the periodicity + +Inf clue + daily-dump location; analyze a `crash.dmp` (winedbg/IDA) with the "24h float timer" hypothesis.

- **H-P0-1 — `PktPlayerInput` (40) has no slot↔source binding.** `SFHeadlessHost.cs:3886-3963`: trusts `slot = data[off+4]`, writes `SlotInputs[slot]`, and sets `_slotV26Endpoint[slot] = from` with no check against the slot owner's address; type-40 bypasses client tracking entirely (`:2295-2300`). Anyone who can reach the port can drive any player's rig and redirect that slot's 30 Hz snapshot stream (deny + leak). - **H-P0-3 — all chat admin commands are unauthenticated.** `TryProcessChatCommand` `:2735-2956`: any connected player can `/kick <slot>`, `/map`, `/restart`, `/tickrate 20..240`, `/anticheat off`, `/weapons`. ### Client (sf-client-recon) — player-side UDP 1339/1340
